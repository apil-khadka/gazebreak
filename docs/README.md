# GazeBreak website

The product site, user guide, and release history are a standalone Node package
built with Vite. The production URL is https://apil-khadka.github.io/gazebreak/.

## Develop

Use Node 22.12 or later. From this directory:

```sh
npm ci
npm run dev
```

Vite serves the site under `/gazebreak/`. Open the URL printed in the terminal.

## Build and verify

```sh
npm test
npm run build
npm run preview
```

`build` refreshes the public release snapshot from the GitHub API, then writes
the site to `docs/dist`. Set `GITHUB_TOKEN` in the build environment to use
authenticated API limits; it is never included in browser code. API failures
stop a production build rather than publishing misleading empty release data.
For offline development, `npm run build:offline` uses the checked-in snapshot.

## Content

- `index.html`: product information and upcoming changes.
- `guide.html`: installation, controls, settings, maintenance, and FAQ.
- `releases.html`: public release history and download links.
- `styles.css`: shared product typography, palette, and responsive layouts.
- `public/releases.json`: saved public release data, generated by `sync:releases`.
- `src/releases.js`: renders Markdown release notes with HTML sanitization.

The site displays the latest release and preview on its homepage, along with a live GitHub star count. A build-time star snapshot remains available when the GitHub API is offline or rate-limited.

Release information comes from published GitHub releases. Drafts are excluded;
experimental releases retain their preview labels. Change release descriptions
on GitHub to update the site's release notes. Keep the manually written
"in development" sections accurate when shipping new versions, and replace
the preview screenshots when the app UI changes.

## Publishing

GitHub Pages uses the GitHub Actions source. `.github/workflows/pages.yml`
builds and deploys changes on `main`, public release edits/publication/deletion,
successful app release workflows, a six-hour schedule, and manual dispatch.
Pull requests build and test without deploying. Successful app release workflows
are included because releases created with `GITHUB_TOKEN` do not trigger another
release-event workflow.

Deployment runs `npm ci`, tests release-data normalization, refreshes releases,
builds the site, uploads the Pages artifact, and deploys it. The project path
defaults to `/gazebreak/`; set `PAGES_BASE_PATH` at build time if migrating to a
custom domain or another repository path.
